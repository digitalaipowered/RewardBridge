## Receiver behavior

The active Supabase `cpx-postback` Edge Function:

1. Accepts GET or POST callbacks.
2. Requires a CPX-listed source IP.
3. Validates `MD5(trans_id-app_secure_hash)` using the private `CPX_SECURE_HASH` Edge Function secret.
4. Redacts the received hash before persisting the raw callback.
5. Treats `out` and other non-payable event types as successful no-op callbacks.
6. Creates pending financial entries only for `status=1` and `type=complete` or `type=bonus`.
7. Treats a later `status=2` as a compensating reversal, not a duplicate.
8. Uses the transaction ID plus status and type for callback idempotency.
9. Verifies `subid_1` and `subid_2` against the mapped RewardBridge project.
10. Cannot release balances while the managed-network switch is disabled.

## Default reward economics

The authoritative gross amount is CPX `amount_usd` in the postback and `payout_publisher_usd` in the survey-list response.

For each valid gross amount:

- RewardBridge platform fee: `25%`
- Risk reserve: `10%`
- Publisher pool: `65%`
- Default end-user share: `70% of the publisher pool`
- Default end-user share of gross before cent flooring: `45.5%`
- Default publisher margin of gross before rounding remainder: `19.5%`

End-user rewards are floored to whole cents so the displayed reward can never exceed the amount credited. The publisher receives the remaining publisher-pool balance.

Examples:

| CPX gross | Platform fee | Reserve | End user | Publisher margin |
|---:|---:|---:|---:|---:|
| $1.00 | $0.25 | $0.10 | $0.45 | $0.20 |
| $2.00 | $0.50 | $0.20 | $0.91 | $0.39 |
| $5.00 | $1.25 | $0.50 | $2.27 | $0.98 |

All provider callbacks first create pending entries. They become available only after the corresponding CPX payment is received and reconciled.
